# 代谢主权 · 微信小程序落地实施指南 V1
## 2 人团队从 0 到上线:步骤、准备、合规红线、时间表

> 用途:判断"能否落地"+ 提供可执行的落地清单
> 时点:2026-06-04
> 核心结论:**技术不是障碍,合规定位 + 糖动对接 是两个真正的前置变量**

---

## 0. 一句话判断

能落地。2 人团队(你 + 技术合伙人)技术上完全够用;真正决定成败的不是写代码,是:
1. **守住"健康管理"合规边界**(绝不碰"医疗服务"类目)
2. **搞定糖动 CGM 数据对接**(商务前置)

---

## 1. 合规红线(落地生死线,最优先)

### 1.1 两条路,只能走第一条

| | ✅ 健康管理路线(走这条) | ❌ 医疗服务路线(2人搞不定) |
|---|---|---|
| 业务 | 生活方式管理、数据记录、习惯陪伴、健康科普 | 在线看诊、疾病咨询、诊断、开药、调药 |
| 资质 | 企业营业执照 + 微信认证(门槛低) | **互联网医院执业许可证**(须医疗机构主体) |
| 名称/文案 | 不得含"医疗/诊断/治疗/处方"等敏感词 | — |

### 1.2 守边界的具体规则(已写入参谋 SOP,此处是合规版)
- ✅ 可以:记录、提醒、陪伴、生活方式建议(饮食/运动/睡眠)、健康科普
- ❌ 不可以:下诊断、判断疾病、给药物/胰岛素剂量、替代医生、宣称"治疗/治愈"
- ❌ 小程序名称、简介、类目均不得出现"医疗""诊疗""诊断"字样
- CGM 数据只做"生活方式参考",不做疾病诊断依据

> **这个边界既是伦理也是合规**:守住它=低门槛健康管理类目;越界=需要互联网医院资质=出局。

### 1.3 ⚠️ 待核实(开工前确认)
- 具体类目选择(健康管理/健康生活 vs 其他医学健康服务)及对应资质——建议向**微信类目审核客服或专业代办**确认,不同细分类目资质要求不同
- 涉及 CGM 血糖数据展示是否触发"医学健康服务"类目——需向微信确认

## 2. 准备工作清单

### 2.1 主体与账号(喜播多数现成)
| 项 | 说明 | 状态 |
|---|---|---|
| 企业营业执照 | 注册小程序主体 | 喜播现成 |

| ICP 备案 | 工信部备案,免费,7-20 天 | 待办 |

### 2.2 技术栈(2人开发)
| 层 | 技术选型 | 难度 |
|---|---|---|
| 小程序前端 | 微信原生 / Taro / uni-app(5屏) | 中低 |
| 后端服务 | 云开发(微信云托管)或自有服务器 + 数据库 | 中 |
| AI 参谋 | 大模型 API(豆包/DeepSeek/通义)+ 校准话术 SOP | 中(核心) |
| CGM 数据 | 糖动 API 对接 / 手动导入兜底 | 依赖商务 |
| 蓝牙设备 | 小程序 BLE API(体重秤) | 中 |
| 数据看板 | 你的运营后台(看依从率/指标) | 低 |

### 2.3 第三方依赖
- **糖动**:CGM 数据 API(需 BD 商务对接 — 命门)
- **大模型厂商**:参谋引擎(API Key + 调用额度)
- **CGM 硬件**:硅基/微泰传感器(种子用户采购)
- **检测机构**:基线+复检抽血(合作一家三甲/第三方检测)

## 3. 开发流程 6 步

```
① 注册企业主体小程序(微信公众平台)
   ↓
② 微信认证(300元,1-3天)→ 开通经营类目权限
   ↓
③ ICP 备案(填信息→微信初审→工信部短信核验→管局复审→下备案号,7-20天)
   ↓ (备案可与开发并行)
④ 开发(微信开发者工具 + 大模型 + 糖动)
   - 体验版测试无须审核
   ↓
⑤ 提交审核(类目合规/内容/隐私,1-3工作日)
   ↓
⑥ 发布上线(熟人种子先小范围灰度)
```

## 4. 2 人分工与工作量

### 4.1 分工
- **你(蒋德铭)**:产品定义、招募、1on1陪伴、每周复盘、话术质检、续费谈话 = "人"侧依从性引擎
- **技术合伙人**:5屏前端 + 后端 + 大模型接入 + 糖动/BLE + 运营看板 = 系统侧

### 4.2 工作量估算(MVP)
| 模块 | 工作量(技术合伙人) |
|---|---|
| 注册/认证/备案 | 并行,主要等待 |
| 5屏前端 | 2-3 周 |
| 后端+数据库+档案 | 1-2 周 |
| AI参谋接入+话术调试 | 2-3 周(与你协作) |
| 糖动API/手动导入 | 1 周(若API顺利) |
| 蓝牙秤+数据看板 | 1 周 |
| **合计** | **约 6-8 周可出可用 MVP** |

> 与 8 周验证周期匹配:边开发边小范围测,不必全做完再上。

## 6. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 类目资质被拒(碰医疗线) | 高 | 严守健康管理定位;名称/文案去敏感词;开工前向微信确认类目 |
| 糖动API对接不成/太贵 | 高 | 降级手动导入,不阻塞验证;同时谈单一CGM厂商SDK |
| 备案周期长(7-20天) | 中 | 提前启动,与开发并行;体验版测试不需备案 |
| 大模型参谋翻车(乱归因) | 中 | 你本人每周质检;设安全边界规则;循证 |
| 隐私合规(健康数据敏感) | 中 | 隐私政策+知情同意;数据加密;不滥用 |
| 2人精力不足 | 中 | MVP砍到最小(3屏先上);非核心留0.1→1 |

## 7. 最小可行起点(如果想更快)

若想最低成本先验证"依从性引擎"假设,甚至可以:
- **第一周用企业微信群 + 共享表格 + 你本人手动跑** 3-5 个种子,验证陪伴+反馈话术是否有效
- 话术跑通了再让技术合伙人开发小程序
- 这样把"产品假设验证"和"技术开发"解耦,降低 sunk cost(沉没成本)

> 即:先用"人肉MVP"证明你的陪伴+归因真的让人改变,再投入开发。这是最 lean 的起点。
