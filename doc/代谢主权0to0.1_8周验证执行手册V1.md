## 1. 招募 SOP(W-1 到 W0)

### 1.1 人群标准(入组门槛)
- 40-55 岁,男性优先(0→0.1 先打你最懂的人群)
- 至少满足代谢综合征 5 项中 1 项:腰围超标 / 甘油三酯高 / HDL 低 / 血压高 / 空腹血糖高
- 高压管理者/企业家(你的圈层),有自我管理意愿
- **排除**:已确诊需药物治疗的糖尿病(超出生活方式管理边界,涉及用药风险)

### 1.2 招募话术(给你本人用)
> "我在做一个针对咱们这种人的代谢健康验证——不是减肥,是把脂肪肝、内脏脂肪、血糖这些中年男人的隐形炸弹管起来。我自己先做的,8 周,戴个动态血糖仪看你每顿饭身体的真实反应,我亲自带你。想不想做我的第一批?"

### 1.3 入组协议(必须签)
- 知情同意:数据用途、隐私保护、非医疗服务声明
- CGM 佩戴知情、检测知情
- 8 周承诺(降低中途流失)

## 2. Day 0 建档 SOP(W0)

| 项 | 内容 | 谁做 |
|---|---|---|
| 基线抽血 | HOMA-IR(空腹胰岛素+血糖)、ApoB、HbA1c、肝功能、血脂 | 合作检测机构 |
| 体成分 | 内脏脂肪面积、肌肉量、体脂率 | 体成分仪/体检 |
| 基础测量 | 腰围、血压、体重 | 自测+蓝牙秤 |
| 戴 CGM | 厂商 App 采集 → 糖动 API 同步到小程序 | 用户+你指导 |
| 目标设定 | 与用户共定 8 周目标(如肝脂肪降一级) | 你 1on1 |
| 建档 | 小程序建立个人档案,参谋读取基线 | 系统 |

**关键**:基线必须 Day0 做齐,否则 8 周后无对比 = 无法证明效果。

## 3. 每日运营 SOP(W1-W8)

| 时刻 | 动作 | 责任 |
|---|---|---|
| 晨 | 用户晨称(蓝牙秤自动同步)+ 能量自评 | 用户 |
| 三餐 | 一句话饮食(语音/拍照)→ 参谋归因餐后血糖 | 用户+AI |
| 全天 | CGM 实时同步,参谋监测异常波动 | 系统+AI |
| 晚 | 今日唯一动作打卡 | 用户 |
| 随时 | 用户找参谋倾诉/提问,参谋归因+校准 | AI |

**摩擦控制**:饮食记录是依从性黑洞,只要"一句话/一张照片",绝不让用户填表。

## 4. 每周复盘 SOP(你本人,关键)

每周固定 1 次,你亲自做:
1. **看数据**:每个用户的依从率、CGM TIR、体重趋势
2. **质检 AI**:抽查 AI 归因记录,标注准不准(沉淀进话术 SOP)
3. **人工兜底**:对掉队用户(依从率<50%)主动 1on1
4. **发周报**:确认每个用户的"方向校准报告"质量

> 这一步既是运营,也是在为 0.1→1 沉淀可规模化的 AI SOP。

## 5. 关键节点

### 第 4 周 · 中检(防流失)
- 轻量检测:指尖血糖、腰围、体重、CGM TIR 趋势
- 给一次中途正反馈:"4 周,你的 X 已经在变好"
- 目的:在 8 周硬反馈之前,先给一次"有效"的证据,稳住士气

### 第 8 周 · 复检 + 续费
- 复检全套硬指标,与 Day0 对比
- "这次和以前不一样"震撼时刻:展示 HOMA-IR/肝脂肪/ApoB 变化
- 续费询问:是否愿意为下一阶段付费

## 6. 红绿线判定(Go / No-Go)

| 验证项 | 红线(No-Go) | 绿线(Go) | 数据来源 |
|---|---|---|---|
| 8周行为依从率 | < 40% | **≥ 60%** | 打卡记录 |
| 真实行为改变次数 | < 2次/人 | ≥ 4次/人 | 参谋记录 |
| 代理指标改善比例 | < 40%用户 | ≥ 60%用户 | 体重/CGM TIR |
| **硬指标改善** | 无明显改善 | **≥ 60%用户某项改善** | 8周复检 |
| 付费续费意愿 | < 40% | ≥ 50% | 询问 |
| 主观价值感知 | 客套"挺好" | 主动说"方向清楚了/有人盯着我/和以前不一样" | 访谈 |

**判定规则**:依从率 + 硬指标改善 两个核心数同时达绿线 = Go;任一触红线 = 严肃复盘是否 No-Go。

## 8. CGM / 糖动对接备忘(核实结论)

| 项 | 结论 |
|---|---|
| 对接方 | **糖动**(国产 CGM 生态聚合平台,硅基/三诺/微泰均已合作) |
| 接入方式 | 厂商 App 采集 → 糖动 → 小程序消费;**非自助开放文档,需商务对接** |
| ⚠️ 待证伪(最高优先) | 糖动 API 的**商务政策、费用、覆盖品牌、技术对接周期** — 这是整个 CGM 方案的命门,应在 W0 前联系糖动 BD 确认 |
| 备选(若糖动不通) | ①用户从厂商 App 手动导出/截图 OCR(最轻,0对接) ②与单一 CGM 厂商直接谈 SDK |
| 0→0.1 容错 | 即便 API 没谈成,先用"手动导入"也能跑通验证,不阻塞 |

## 9. 风险与应急

| 风险 | 应急 |
|---|---|
| 低血糖(CGM<3.9) | 参谋安全提示 + 建议就医,不自行处理 |
| 用户中途流失 | 你本人 1on1 兜底;W4 中检前是流失高发期 |
| 糖动 API 未谈成 | 降级为手动导入,不阻塞验证 |
| 依从率低 | 复盘是"动作太多"还是"反馈太弱",优先减动作、强反馈 |
| 发现严重疾病征兆 | 立即建议线下就医,留存沟通记录 |
